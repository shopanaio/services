# Catalog Migrations Domain Inventory

Inventory date: 2026-08-09.

This is the accepted final-schema inventory for the handwritten catalog `node-pg-migrate` baseline under `services/catalog/migrations/domains/**`.

Canonical source files:

- `services/catalog/src/repositories/models/index.ts`
- `services/catalog/src/repositories/models/**/*.ts`

DDL conventions used by the baseline:

- `catalogSchema = pgSchema("catalog")` maps to `CREATE SCHEMA IF NOT EXISTS "catalog"`.
- Locale and currency columns use Catalog-owned PostgreSQL enums
  `catalog.locale_code` and `catalog.currency_code`.
- Drizzle `timestamp(..., { withTimezone: true, mode: "string" })` maps to `timestamp with time zone`.
- Drizzle `.defaultNow()` maps to `DEFAULT now()`.
- UUID defaults use the standard PostgreSQL `uuidv7()` function.
- Drizzle `bigint(..., { mode: "number" })` maps to PostgreSQL `bigint`; mode is TypeScript/runtime serialization only.
- Drizzle `jsonb()` maps to `jsonb`; `text().array()` maps to `text[]`; `integer().array()` maps to `integer[]`.
- All foreign keys are `MATCH SIMPLE`, `ON UPDATE NO ACTION`, and `NOT DEFERRABLE` unless the model explicitly represents otherwise. No model currently represents deferrability.
- When Drizzle model code does not provide a constraint name, this baseline chooses stable explicit names: `{table}_pkey`, `{table}_{column}_fk`, `{table}_{columns}_unique`.
- No foreign key is added where the runtime model lacks `.references()` or `foreignKey(...)`, even when a comment implies a relationship.

## Non-DDL And Gap Decisions

| Source | Decision |
| --- | --- |
| `schema.ts` / `catalogSchema` | Creates the schema object and is represented by `CREATE SCHEMA IF NOT EXISTS "catalog"`. |
| `catalog-refs.ts` / `catalogVariant` | Compatibility-only reference object. It is not exported from `models/index.ts`, duplicates the canonical `variant` table partially, and is intentionally not assigned to a separate DDL file. |
| `product-inventory-settings.ts` comment says product FK exists | The model has no `.references()` or `foreignKey(...)`; the baseline does not create that FK. |
| Media file IDs, product/item reference IDs, variant IDs in inventory/cost/bulk tables | No cross-service or implied FK is added unless the runtime model declares it. |
| Deferrability | Runtime-model foreign keys use PostgreSQL defaults. The SQL-only component-target completeness constraint triggers are `DEFERRABLE INITIALLY DEFERRED` so registry and subtype rows can be written in one transaction. |
| Component target subtype completeness | Drizzle models express subtype-to-registry FKs but cannot express the reverse “every registry row has a matching subtype” assertion. `0804_components__target_integrity.sql` adds deferred constraint triggers and makes `component_target` the only deletion owner. |
| Dependency action price-rule cleanup | Drizzle cannot represent row-delete triggers. After direct, rule-cascade, or target-cascade action deletion, `1102_dependencies__actions.sql` deletes the candidate `component_price_rule` only when no component item, pricing template, or remaining dependency action references it. Repository cleanup applies the same reachability check. |
| Comparison semantic integrity | Drizzle models express structural keys, typed payload checks, and ownership FKs. Cross-table leaf-feature validation, feature/option/N/A source exclusivity, SINGLE-cardinality enforcement for option bindings, and protection against changing a populated canonical unit are implemented by PostgreSQL triggers in `0455_comparison__integrity.sql` and must also be validated by management scripts for actionable user errors. |
| `dbos.transaction_completion` | This is an infrastructure table required by `@dbos-inc/postgres-datasource@4.23.6`, not a Catalog Drizzle model. It stores the durable transaction output/error checkpoint with primary key `(workflow_id, function_num)` in the same physical database as Catalog writes. |
